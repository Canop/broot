    escaping to define if you try to fit it in one string, so I'll base the syntax of

Let's imagine the multiple selection (eg the stage) contains
    /a/foo.txt and /b/bar.txt

An `external` is usually defined as an array of strings, for example

{
    external: [ "more" "{file}" ]
}

With this definition, when the selection is multiple, broot calls the command once per file, that is it would call successively
"more" "/a/foo.txt"
"more" "/b/bar.txt"

What I propose is to allow specifying that a token is either *repeated* or *repeating* in case of multiple selection.

Example 1:

{
    external: [
        "more"
        { repeated: "{file}" }
    ]
}
result:
"more" "/a/foo.txt" "/b/bar.txt"

Example 2:

{
    external: [
        "truc.exe"
        {
            repeated: ["-p", "{file}"]
        }
    ]
}
result:
"truc.exe" "-p" "/a/foo.txt" "-p" "/b/bar.txt"

Example 3:

{
    external: [
        "smerge"
        "--files"
        {
            repeating: "{file}"
            separator: ","
        }
    ]
}
result:
"smerge" "--files" "/a/foo.txt,/b/bar.txt"

Example 4:

{
    invocation: "back {version}"
    external: [
        "backup.exe"
        {
            repeated: [
                "-i" "{file}" "-o" "{directory}/{file-stem}-{version}{file-dot-extension}"
            ]
        }
    ]
}
result assuming user typed "3" for "version":
"backup" "-i" "/a/foo.txt" "-o" "/a/foo-3.txt" "-i" "/b/bar.txt" "-o" "/b/bar-3.txt"
